# Refine milestone (2026-11) — Web Picker ergonomics + board command args

Agent-facing design record. English-only by policy (`docs/milestones/**` is not paired).
Terminology follows `CONTEXT.md` (Web Picker, Marker, Pick, Record, Board, Card, Entry, Handoff).
Milestone theme: **refine existing behaviour, add no new feature surface.**

Status: brainstorm + design nodes done; user approved every plan below.
Implementation is tracked in the `implement-and-verify` node of the same workflow run.

## 1. Feature order

1. **F2** — delete three global hotkeys (keep pick-mode keys)
2. **F4** — trigger show/hide (hotkey re-purposed + edge nub, per-domain memory)
3. **F3** — initial / re-show placement at the mouse position
4. **F6** — highlight existing Markers when the panel is open
5. **F1** — auto-connect becomes an explicit per-domain whitelist
6. **F5** — `board new` / `board write` argument handling

F2–F4–F3–F6 touch the same userscript: one `npm run build`, one manual verification pass
(user verifies the Web Picker by hand — the `verify` skill is **not** required for it).
F1 is a separate commit (`PAGE_QUERY_RULE` promise change included).
F5 is pure TypeScript with a unit test.

Every step: `npm test` green before commit; `dist/web-picker.user.js` rebuilt and committed
after the userscript steps (F2, F4, F3, F6, F1).

## 2. Out of scope

- Mesh transport changes, board auto-cleanup/archival, `mcp-gateway`, admin-page features,
  new page-capture capabilities.
- Persisting the trigger position to GM storage (position stays `sessionStorage` only).
- A `--flag` argument system or a general shell-like quote parser for slash commands.
- Adding a body/intent flag surface to `board new` beyond the title.

## 3. F2 — delete three global hotkeys

Approach
- `web-picker.src/ui/hotkeys.js`: drop `isRecHot`, `isList`, and the `isHot` picker start/stop
  branch. Keep `KeyF` (freeze, pick mode only) and every `document`-level key
  (`Escape` / `Enter` / `Backspace`).
- All three actions keep mouse entry points that already exist: panel = trigger hover fan-out
  + right click; record = fan-out row + panel empty-state button (`ui/panel.js`);
  pick = click on the trigger body (`ui/fab.js`).
- Tampermonkey menu entries `menu.openPanel`, `menu.startPick`, `menu.toggleRecord` **stay**
  (decided): they are the recovery path for a hidden trigger (F4) and are menus, not hotkeys.
  Only their `(⇧⌥X)` hints are removed from the strings.
- Copy cleanup: `i18n.js` (6 strings with `⇧⌥X`), `main.js` debugLog line, `banner.js` header
  comment and `@description`, `docs/dev/web-picker.md` + `web-picker.zh.md` hotkey table
  (remove the three rows, keep pick-mode rows).

Touched: `web-picker.src/ui/hotkeys.js`, `web-picker.src/main.js`, `web-picker.src/i18n.js`,
`web-picker.src/banner.js`, `docs/dev/web-picker.md`, `docs/dev/web-picker.zh.md`, `dist/`.

Risks
- `banner.js` comments must not lose the pick-mode key documentation.
- `src/docs-pairs.test.ts` requires the two docs to stay structurally identical — change both
  in the same edit.

## 4. F4 — trigger show/hide with edge nub

Approach
- New per-domain key `wp.fabHidden.<origin>` in GM storage, helper `fabHiddenKey(origin)` in
  `web-picker.src/storage.js` (same shape as `autoLinkKey`, but deliberately **not** in
  `broker-conn.js` — hiding is unrelated to the broker).
- `HOTKEY` (`constants.js`) keeps its chord; the semantics change to "toggle trigger
  visibility". The `hotkeys.js` branch only calls `ctx.toggleFab()`.
- Hidden state renders the trigger at the same position as a 10px semi-transparent dot
  (CSS class); hover restores the full 36px control. No reflow, so F3's position semantics hold.
- Conflict to resolve: `ui/pick.js` `setActive()` toggles the trigger with an inline
  `elFabStack.style.display`. Replace that with a class so it cannot fight the hidden class.
- Menu item `menu.toggleFab` with state-dependent label.

Touched: `constants.js` / `storage.js`, `ui/hotkeys.js`, `ui/fab.js`, `ui/shadow.js` (CSS),
`ui/pick.js`, `main.js`, `i18n.js`, both docs, `dist/`.

Risks
- Mixing `sessionStorage` (per-tab, position) and GM storage (cross-tab, hidden flag) is the
  easiest mistake here.
- The clamp in `ui/shadow.js` must still hold for the collapsed dot.

## 5. F3 — first placement at the mouse position

Approach
- Current init is "default bottom-right, then `sessionStorage` overrides". New order:
  saved position first; otherwise the mouse position; otherwise the default corner.
- Timing: injection usually happens before any pointer event. Record `lastPointer` inside the
  existing window `pointermove` capture listener in `ui/fab.js` (before its early return), and
  when no saved position exists, defer placement until the first `pointermove`; fall back to
  the default corner after ~400ms without a pointer event so the trigger can never stay
  invisible.
- Reuse the existing `clampFabPos`.

Touched: `ui/fab.js`, `ui/shadow.js`, `dist/`.

Risks
- Brief wrong-position window before placement — keep it `visibility:hidden` until placed to
  avoid a visible jump.
- Iframes / narrow viewports: coordinate clamping is the only guard.

## 6. F6 — highlight existing Markers while the panel is open

Approach
- Every Pick already stores `selector` (cssPath) and `xpath` (`ui/pick.js` `payloadFor`).
  Add `resolvePick(rec)`: `document.querySelector(rec.selector)` in try/catch (a cssPath may
  throw) → fall back to `document.evaluate(rec.xpath)` → otherwise treat as unresolved.
- Overlay: mirror `renderGroupMarks` — a `#pmarks` container in the shadow root plus `.pmark`
  styles, visually distinct from the amber group marks. Pick mode and the open panel are
  mutually exclusive, so the two overlays rarely coexist.
- Lifecycle: `openPanel()` renders marks; `closePanel()` clears them. While open, listen to
  `scroll` / `resize` (`{ passive: true, capture: true }`) and recompute rects in a
  requestAnimationFrame-throttled pass (fixed positioning against viewport coordinates means
  scrolling must recompute).
- Badge numbers match the panel row index (the batch index used by `renderPanel`'s `data-i`).
- Read-only: no page DOM/CSS mutation, no new storage.

Decided: unresolved markers are **skipped silently** — the panel rows are left untouched
(the element may simply be behind a closed modal or collapsed).

Touched: `ui/pick.js` (or a new `ui/marks.js`), `ui/shadow.js` (markup + CSS), `ui/panel.js`,
`i18n.js` if a hint string is added, both docs, `dist/`.

Risks
- Recompute cost on scroll: rAF throttle, draw only in-viewport items.
- A selector can resolve to a different element after the page mutates; accepted for a
  read-only overlay, worth a line in the docs.
- Confirm z-order against `#gwrap`.

## 7. F1 — auto-connect becomes an explicit per-domain whitelist

Approach
- Remove the auto-grant in `broker-conn.js`: a successful manual connect no longer writes
  `wp.autoLink.<origin> = true`. Whitelist entry = that key being `true`; no new key.
- `autoLinkAllowed()` / `revokeAutoLink()` / `policyBlockedKey` semantics unchanged, only the
  automatic growth of the whitelist disappears.
- Authorization entry point: the `elSAuto` checkbox in `ui/settings.js` already writes
  `autoLinkKey(location.origin)` — it becomes the whitelist switch (copy update in `i18n.js`;
  it must no longer claim "authorized after one manual connect").
- Menu `menu.revokeAuto` becomes "disable auto-connect for this domain"; optionally a
  whitelist listing item that scans `GM_listValues` for the `wp.autoLink.` prefix.
- Silent policy probe for unlinked origins is kept as-is.

Decided
- A manual connect keeps the connection alive for the current page load (`manualDown`
  semantics untouched); it simply does not persist an authorization.
- `PAGE_QUERY_RULE` must be reworded to be conditional ("auto-reconnect applies when this
  page is whitelisted"), because the current text promises unconditional reconnect and would
  make an agent retry forever.

Touched: `broker-conn.js`, `ui/settings.js`, `main.js`, `i18n.js`, both docs, `dist/`.

Risks
- Users who rely on today's auto-reconnect will notice the change after upgrading; the
  release note must state it.
- The `PAGE_QUERY_RULE` promise and the whitelist default must land in the same commit.

## 8. F5 — board command arguments

Approach
- Do not touch the `split(/\s+/)` tokenizer (`src/commands.ts`). Inside the `board` branch only,
  strip a matching pair of surrounding quotes from `rest.join(" ")` (both `"` or both `'`).
- `board new [title...]`: already accepts multi-word titles; add the quote strip and make the
  help text explicit.
- `board write <id> [text...]`: text becomes optional. With text, keep the current intent
  phrasing; without text, run the same two-phase `board-entry` prompt shape that `new` uses
  (no more `Usage:` error).
- Sync the help block, the command completions descriptions, and any doc mention.
- Extract the quote-stripping into a small pure function and unit-test it (the `commands.ts`
  parsing has no test coverage today).

Decided: string arguments stay positional with no `--flag` surface; no general quote parser.

Touched: `src/commands.ts`, `src/board/board.test.ts` or a new `src/commands.test.ts`, docs if
they mention the syntax. No `dist/` change.

Risks
- A title that legitimately starts and ends with the same quote character loses them;
  acceptable because only matched pairs are stripped.
- The no-text `board write` path depends on the agent returning a `board-entry` block — same
  mechanism as `board new`, so no new failure mode.
